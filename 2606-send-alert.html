ErrorAlert 錯誤警報系統建議規劃書

為確保系統的簡訊 (SMS)、信件 (Email) 及推播 (Push) 發送失敗，以及與 HIS 同步等業務發生異常時，能夠即時但「控頻不洗版」地通知維運人員。本文件提供可點擊操作的模擬介面，以驗證設計之正確性。

核心架構決定： 本系統排除 File Log 的解析，僅針對已寫入 DB 或主動呼叫警報 API 的事件進行「動態計數與冷卻」。

2. 警報判定流程

每當發生錯誤並調用 ErrorAlert::trigger() 時，系統在後端進行的完整判定流程圖：

flowchart TD A["呼叫 ErrorAlert::trigger($key, $details)"] --> B{"DB 中是否有此 config?"} B -- 否 --> C["1. 動態補救新增該 config
設定 is_enabled = 0
其他欄位設為預設或 NULL
自動產生 UUID，admin_id = NULL"] C --> E["結束流程
(第一次錯誤不發送警報)"] B -- 是 --> D{"config.is_enabled == 1?"} D -- 否 --> E D -- 是 --> F{"2. 查詢該 error_type 最新的一筆計數器?"} F -- 有 --> G{"3. 該列 created_at >= NOW - 10 分鐘?"} F -- 無 --> H["4. 執行 SQL INSERT
count = 1
created_at / updated_at = NOW"] G -- 是 --> I["5. 執行 SQL UPDATE
current_count = current_count + 1
last_error_message = $details
updated_at = NOW"] G -- 否 --> H H --> E I --> J{"檢查該區間的 count >= 閥值?"} J -- 否 --> E J -- 是 --> K{"檢查當前時間與 config.last_sent_at
是否大於 cooldown_minutes?"} K -- 否 --> E K -- 是 --> L["6. 觸發警報發送
帶入最後一次錯誤訊息"] L --> M["7. 更新 config.last_sent_at = NOW"]

3. 資料表設計 (3張核心表)

3.1 警報設定表 error_alert_configs

欄位名 類型 說明
idINT (PK)自增識別碼
uuidCHAR(36)唯一識別碼 (UNIQUE，用於 API 識別)
error_typeVARCHAR錯誤類型 KEY (UNIQUE，來自 Enum)
threshold_countINT觸發閥值（達到此值發送警告，如 5）
check_intervalINT檢測區間（單位：分鐘，預設如 10）
cooldown_minutesINT冷卻時間（單位：分鐘，預設如 60）
sms_templateTEXT簡訊內容範本
email_templateTEXTEmail 內容範本
is_enabledTINYINT是否啟用 (0: 停用, 1: 啟用)
admin_idINT最後更新人員 ID (外鍵，指向 sys_users.id)
last_sent_atDATETIME最後一次發送警報時間 (跨區間冷卻判定基準)

3.2 通知聯絡人主表 error_alert_recipients

欄位名 類型 說明
idINT (PK)自增識別碼
uuidCHAR(36)唯一識別碼 (UNIQUE)
recipient_nameVARCHAR姓名
phoneVARCHAR手機號碼 (簡訊發送)
emailVARCHAR電子郵件 (郵件發送)
is_disabledTINYINT是否停用 (0: 啟用, 1: 停用)
admin_idINT最後更新人員 ID

3.3 警報計數與歷史表 error_alert_counters

★ 資料庫複合索引：INDEX idx_type_created (error_type, created_at)

欄位名 類型 說明
idINT (PK)自增識別碼
error_typeVARCHAR錯誤類型 KEY
current_countINT此區間內累計錯誤次數
last_error_messageTEXT此區間最後一次發生的錯誤訊息
created_atDATETIME此輪第一次發生時間 (代表區間起點)
updated_atDATETIME此輪最後一次更新時間
